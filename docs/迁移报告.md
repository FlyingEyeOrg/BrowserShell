## 三、结构变更（方案 A）

`BrowserShell.Runtime` 可执行项目**已删除**，原因与处理：

- 删除 `App.xaml` / `App.xaml.cs`（31 行 WPF 入口）

## 四、迁移中发现并修复的缺陷

| # | 问题 | 成因 | 处理 |

## 六、待决与未竟项

1. ~~命名对称性~~ **已解决**：17 个 Page 专属公共类型 + 6 个 Page 专属内部类型已改名为 `PageWindow*`，与既有 `PageWindows` / `IPageWindowService` / `PageWindowService` 命名族对齐；`BrowserWindow*` 与 `PageWindow*` 形成对称的用途对比。2 个共享类型（`WindowTitleBarOptions`、`WindowManagementOptions`）保持原名。

> 说明：曾评估 `WebViewWindow*` / `WebWindow*` / `WebPageWindow*`，均**否决**——BrowserWindow 与 PageWindow 同为 WebView2 渲染（`BrowserWindow.cs:19`、`ShellWindow.cs:23` 均为 `new WebView2()`），"Web" 限定词对两者都成立、零区分度；且 `WebPageWindow` 恰是 BrowserWindow 的准确描述，会造成指向相反的误导。
2. **SoftwareHub 侧接入（按你的要求暂缓）**：`src/SoftwareHub.Service.SDK.Hosting/Desktop/` 7 个文件、约 980 行。实测三个障碍：
   - SoftwareHub 使用的 43 个 SDK 类型中 **36 个是 internal**，原先靠 `InternalsVisibleTo` 越权访问；迁移后**必然编译失败**
   - 该适配层反向引用 `IServiceEventBus`、`ServiceHostOptions`、`ServiceInstanceIds`、`ServiceManagementMode`，迁入 BrowserShell 会**形成循环依赖**
   - `ServiceDesktopPageWindowEventSink` 是 `IServiceEventBus` 的适配器
   - 结论：它**本质属于 SoftwareHub 对 BrowserShell 的适配层**，应留在 SoftwareHub 并改为引用 NuGet 包。`AgentWindow`、`AgentClientRegistration`、`BrowserShellHubMethods` 等 36 个类型的公开化是接入的前置条件。
3. `SoftwareHub` 侧原有 `src/SoftwareHub.DesktopAgent` 与 `src/SoftwareHub.DesktopAgent.Runtime` **仍原样保留**，未做任何改动，SoftwareHub 仍可正常编译。

## 七、WebView.Wpf 瘦身（后续重构）

初版迁移把整个桌面侧代理（Kestrel/SignalR/会话/授权/快照/窗口管理）都放进了
`BrowserShell.WebView.Wpf`，超出"基础 Web 套壳"的定位。已按职责重新切分：

### 窗口边框外包给 WindowChromeKit

原生窗口边框能力已由独立的 **`WindowChromeKit.Wpf`**（2.1.0，nuget.org 公开包）提供，
其 `ChromeWindow` 覆盖了本项目原先自带的全部 chrome 实现。因此删除：

| 删除内容 | 文件数 | 现由谁提供 |
|---|---|---|
| `Windows/Frame/`（WindowFrame / HitTest / ResizeOverlay） | 3 | `ChromeWindow` |
| `Windows/Interop/`（NativeWindowMethods 等） | 12 | `WindowChromeKit.Wpf.Internal` |
| `Windows/Icons/` | 1 | `WindowChromeIcons` |
| `TitleBarOptions.cs` | 1 | `ChromeTitleBarStyle` / `ChromeTitleBarPalette` / 颜色属性 |
| `app.manifest`（DPI） | 1 | 由 WPF/`ChromeFrame` 处理 |
| `Assets/BrowserShell.ico` | 1 | `WindowChromeIcons.Windows10` |

### 代理层全部删除

代理运行时（Kestrel 宿主、SignalR 客户端/服务端、会话、授权、快照、窗口管理、
`ShellWindow` / `BrowserWindow` 派生窗口）已整块删除，由 SoftwareHub 旧项目兜底。

### 结果

`BrowserShell.WebView.Wpf`：**57 文件 / 6630 行 → 11 文件 / 1149 行**

公开 API（5 个类型）：

| 类型 | 说明 |
|---|---|
| `WebViewShell` | 外壳管理器：创建/跟踪/关闭窗口，持有进程内唯一 WebView2 环境 |
| `WebViewWindow` | 单个外壳窗口，派生自 `ChromeWindow` |
| `WebViewWindowOptions` | 窗口设置 |
| `WebViewWindowClosingContext` | 关闭裁决上下文 |
| `WebViewWindowEnvironment` | 底层 WebView2 环境与隔离 Profile |

依赖收敛为：`Microsoft.Web.WebView2` + `WindowChromeKit.Wpf`（不再依赖
`Microsoft.AspNetCore.App`、SignalR、Serilog）。

同时清理了 `Directory.Packages.props` 中 4 个不再使用的 Serilog 版本声明。
